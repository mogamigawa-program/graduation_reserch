トランザクションとは？

トランザクション＝複数操作をまとめて扱う単位

トランザクションとは、複数のSQL操作を「ひとまとまり」として扱う仕組みです。
まとめて実行し、最後に確定（COMMIT）するか、取消（ROLLBACK）するかを選べます。

イメージ： 「一連の作業をまとめて行い、最後に“確定する”か“なかったことにする”か決める」

基本操作（BEGIN / COMMIT / ROLLBACK）

トランザクションは、BEGIN（開始）で始め、最後に COMMIT（確定）またはROLLBACK（取消）で終わります。

BEGIN; -- トランザクション開始（START TRANSACTIONでもOK） -- ここに複数のSQLを書く（例：UPDATE / INSERT / DELETE） COMMIT; -- 変更を確定（ここで初めて反映が確定する） ROLLBACK; -- 変更を取り消す（BEGIN以降の変更をなかったことにする）

考え方：確定前は「途中状態」

BEGIN 〜 COMMIT の間は、変更が行われていてもまだ確定していない途中状態です。
この状態では、ROLLBACKすれば取り消せるのが大きなポイントです。

ポイント： COMMITするまでは「やっぱやめた」ができる（ROLLBACKで取り消し可能）

考え方：確定後は元に戻せない（通常）

COMMIT を実行すると変更が確定し、基本的には元に戻せません。
（元に戻すには、逆の操作を自分で実行する必要があります）

注意： COMMIT後はROLLBACKでは戻せない（通常）
💡 Tips：1文でもトランザクションって知ってた？

UPDATE / INSERT / DELETE は、BEGINを書かなくても、 DBが内部で自動的に1つのトランザクションとして処理することがあります（自動コミット設定の場合）。

-- これを1文だけ実行すると… UPDATE accounts SET balance = balance - 1000 WHERE name = 'A'; --（自動コミットなら）内部的には「実行して確定」まで進むイメージ

明示的に BEGIN してトランザクションを使うのは、複数の処理をまとめて安全に扱いたいときです。
