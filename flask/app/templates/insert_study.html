INSERT文とは

INSERT文は、テーブルに新しいデータ（レコード）を追加するときに使うSQL文です。
たとえば、新しいユーザー情報や商品データなどを登録したいときに使います。

基本形（いちばん大事）

INSERT は「どの列に」「どんな値を」入れるかを指定します。
基本は、列名（columns）を指定する形で書くのがおすすめです。

INSERT INTO テーブル名 (列1, 列2, ...) VALUES (値1, 値2, ...);

例：users テーブルに name と age を追加

INSERT INTO users (name, age) VALUES ('田中太郎', 25);

文字列のクオートと日付の書き方

値の書き方は「型」によって変わります。DBごとの細かい違いはありますが、まずは次のルールで覚えると安全です。

  • 文字列：' '（シングルクォート）で囲む
  • 数値：クォートは付けない
  • 日付：基本は 'YYYY-MM-DD' の形で書く（シングルクォート付き）
-- 文字列（' 'で囲む） INSERT INTO users (name) VALUES ('佐藤花子'); -- 数値（囲まない） INSERT INTO users (age) VALUES (30); -- 日付（'YYYY-MM-DD' の形で囲む） INSERT INTO users (birth_date) VALUES ('2000-04-01');

よくあるエラーの考え方

INSERT がうまくいかないときは、だいたい次の3つのどれかです。
エラーメッセージを見たら、まずこの3点を疑うと原因に辿り着きやすいです。

① 列数と値数は一致しているか

(列1, 列2, ...) と VALUES (値1, 値2, ...) は、個数が一致している必要があります。

-- ❌ 列は2つなのに値が1つ INSERT INTO users (name, age) VALUES ('田中太郎');
-- ✅ 個数を合わせる INSERT INTO users (name, age) VALUES ('田中太郎', 25);

② 型の整合性は合っているか

列のデータ型（INT, DATE など）に対して、入れる値が不自然だとエラーになったり、意図しない変換が起きたりします。
例：INT列に文字列、DATE列に不正な日付 など。

-- ❌ INT列に文字列（age が INT の想定） INSERT INTO users (age) VALUES ('twenty');
-- ✅ INT列には数値 INSERT INTO users (age) VALUES (20);

③ 制約違反していないか（NOT NULL / PRIMARY KEY / UNIQUE など）

テーブルには「入れてはいけない値」を防ぐための制約が付いていることがあります。
代表的なのは次の2つです。

  • NOT NULL：値が必須（NULL禁止）
  • PRIMARY KEY / UNIQUE：重複禁止
-- ❌ NOT NULL の列に値を入れていない（name が NOT NULL の想定） INSERT INTO users (age) VALUES (25); -- ❌ PRIMARY KEY/UNIQUE の重複（id が一意の想定） INSERT INTO users (id, name, age) VALUES (1, '山田太郎', 20); INSERT INTO users (id, name, age) VALUES (1, '佐藤花子', 30);

すべての列に値を入れる場合（列名省略）

すべての列に順番通りに値を入れる場合は、列名を省略できます。 ただし、列の順番を間違えるとエラーや事故が起きやすいので、基本は列名を書くのがおすすめです。

INSERT INTO users VALUES (1, '田中太郎', 25);

複数行をまとめて追加する

複数のレコードを一度に追加できます（VALUES をカンマでつなぐ）。

INSERT INTO users (name, age) VALUES ('佐藤花子', 30), ('鈴木一郎', 22), ('山田二郎', 28);

まとめ

  • 基本形は INSERT INTO ... (columns) VALUES (...)
  • 文字列と日付は基本 ' ' で囲む（例：'2026-02-03'）
  • エラー時は「列数=値数」「型」「制約」の3点をチェック
