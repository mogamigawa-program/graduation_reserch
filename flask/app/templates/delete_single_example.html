DELETE文（単数条件）実行例

このページで見ること

  • 削除前テーブル → DELETE実行 → 削除後テーブルを並べて、差を確認する
  • 典型エラー（列名誤記／クオート誤り／型不整合）を見て「何を直すか」を理解する
  • 対象が0件で終わるケースも扱い、意図と結果のズレに気づけるようにする

対象が0件で終わる（意図と結果のズレ）

DELETEは実行できても、条件に合う行がなければ何も削除されません。
だからこそ、削除前にSELECTで確認するのが重要です。

-- ① まず確認（0件） SELECT * FROM products WHERE product_name = 'はさみ';
SELECT結果（0件）
product_idproduct_nameprice
（条件に一致する行がありません）
-- ② DELETEしても削除される行は0件 DELETE FROM products WHERE product_name = 'はさみ';

学び：「実行できた」＝「削除された」とは限らない（0件のことがある）

よくあるエラー例（典型）

※英語エラーは MySQL/MariaDB でターミナルに出がちな代表例です（環境により文言は少し変わります）。

❌ 列名の誤記（Unknown column）
DELETE FROM products WHERE id = 3;

原因： products の列は product_id なのに id と書いている

直し方： 正しい列名に直す（product_id を使う）

ターミナルでのエラーメッセージ例（英語 / MySQL）

mysql> DELETE FROM products WHERE id = 3;
ERROR 1054 (42S22): Unknown column 'id' in 'where clause'
⚠ クオート誤り（文字列を ' ' で囲まない）
DELETE FROM products WHERE product_name = はさみ;

原因： 文字列なのにクオートが無い → DBは「列名」だと思ってしまう

直し方： 'はさみ' のようにシングルクォートで囲む

ターミナルでのエラーメッセージ例（英語 / MySQL）

mysql> DELETE FROM products WHERE product_name = はさみ;
ERROR 1054 (42S22): Unknown column 'はさみ' in 'where clause'
⚠ 条件値の型不整合（意図した一致にならない／0件になる）

DBによっては「エラー」ではなく「暗黙変換」されて、0件になって気づきにくいことがあります。

-- price は数値(INT)なのに、文字列っぽい値を入れてしまう例 DELETE FROM products WHERE price = 'abc';

起こりうること： エラーにならず、結果が0件（または意図しない判定）になる場合がある

直し方： 数値列には数値で条件を書く（price = 100 など）

ターミナルでのメッセージ例（英語 / MySQL）

mysql> DELETE FROM products WHERE price = 'abc';
Query OK, 0 rows affected (0.00 sec)

※SQLモードによっては警告が出ることがあります（例：Truncated incorrect DECIMAL value）。

補足：削除前の確認方法（安全な手順）

削除前に対象データを確認するには、SELECT文を使いましょう。

SELECT * FROM products WHERE price = 100;
