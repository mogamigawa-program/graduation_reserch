INSERT + SELECT文とは

INSERT + SELECT は、別テーブルのデータをSELECTで取り出し、その結果をまとめて別テーブルへ挿入するSQLです。
「データのコピー」「条件に合う行だけ移す」「集計結果を別テーブルに保存する」などでよく使われます。

基本形

VALUES の代わりに SELECT を書くのがポイントです。

INSERT INTO 挿入先テーブル (挿入先カラム1, 挿入先カラム2, ...) SELECT 取り出す列1, 取り出す列2, ... FROM 元テーブル WHERE 条件;

重要ルール：カラム数を一致させる

INSERT + SELECT では、挿入先に指定したカラム数と、SELECTで返す列数が 必ず一致している必要があります。

-- ✅ OK（3列 → 3列） INSERT INTO A (c1, c2, c3) SELECT x, y, z FROM B;
-- ❌ NG（3列 → 2列：列数が足りない） INSERT INTO A (c1, c2, c3) SELECT x, y FROM B;

また、列数だけでなく、型（INTに文字列を入れないなど）も整合している必要があります。

WHEREで挿入件数が変わる

WHERE 条件を付けると、SELECTで取れる行数＝挿入される行数になります。
つまり、条件次第で 0件 / 1件 / 複数件と挿入件数が変わります。

-- age >= 30 の人だけを挿入（条件に合う人数分だけ行が追加される） INSERT INTO senior_users (id, name, age) SELECT id, name, age FROM users WHERE age >= 30;

制約違反が起きる可能性

INSERT + SELECT は複数行をまとめて挿入できる反面、挿入先テーブルの制約に違反するとエラーになることがあります。

  • PRIMARY KEY / UNIQUE：同じ値が入ろうとすると重複エラー
  • NOT NULL：NULLが入ろうとするとエラー
  • 外部キー（FOREIGN KEY）：参照先に存在しない値だとエラー
-- 例：senior_users.id が PRIMARY KEY の場合 -- users 側に id の重複がある/すでに入っているとエラーになる可能性がある

うまくいかないときは、「列数」「型」「制約」のどれが原因かを切り分けるのがコツです。

まとめ

  • INSERT INTO A (...) SELECT ... FROM B ... の形で、SELECT結果をまとめて挿入できる
  • 挿入先カラム数とSELECTの列数は必ず一致させる
  • WHERE によって挿入件数が変わる（0件〜複数件）
  • 制約（PRIMARY KEY / NOT NULL など）違反でエラーになることがある
