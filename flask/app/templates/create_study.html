テーブルの作成（CREATE TABLE）

CREATE TABLE 文とは？

テーブルを新しく作るための SQL 文です。
「どんな列（カラム）を作るか」「それぞれにどんな値を入れるか（データ型）」 「最低限どんなルール（制約）を付けるか」を決めます。

基本構文（超重要）

CREATE TABLE は、テーブル名を書いて、括弧の中に列定義を並べます。
列定義は カンマ区切りです（最後の行にはカンマを付けません）。

CREATE TABLE テーブル名 ( 列名 データ型 [制約], 列名 データ型 [制約], ... );
よくある注意
  • 列定義は カンマ区切り（不足/余分なカンマでエラーになりやすい）
  • 括弧 ( ) と文末の ; を忘れない

代表的なデータ型と「どの値を入れるか」

データ型は「その列に入れる値の種類」を決めます。
まずは以下の 3 種類を押さえれば十分です。

種類 データ型（例） 入れる値のイメージ 例
整数 INT 年齢、個数、ID など（小数なし） 18 / 250 / 1
文字列 VARCHAR(50) 名前、メール、商品名など（文字） "Sato" / "apple"
日付 DATE 生年月日、登録日、購入日など（日付） 2026-01-30
VARCHAR(50) って何？

VARCHAR(50) は「最大 50 文字まで入る文字列」です。
名前なら 50、商品名なら 100 など、用途に合わせて長さを決めます。

最低限の制約と役割（PRIMARY KEY / NOT NULL）

制約は「データを正しく保つためのルール」です。
初学者はまず PRIMARY KEY と NOT NULL を覚えると実務でも困りにくいです。

制約 役割 何を防ぐ？ よく使う場所
PRIMARY KEY 行（レコード）を一意に識別する 重複・NULL を防ぐ ID（番号）
NOT NULL 必ず値を入れさせる 欠損（NULL） を防ぐ 名前、登録日など
PRIMARY KEY のイメージ

同じ id が2つあると困るので、PRIMARY KEY を付けて重複を禁止します。
さらに PRIMARY KEY の列は NULL も禁止になります。

例：users テーブルを作る（基本の形）

CREATE TABLE users ( id INT PRIMARY KEY, name VARCHAR(50) NOT NULL, age INT );
  • id INT PRIMARY KEY：ユーザーを識別する番号（重複・NULL を防止）
  • name VARCHAR(50) NOT NULL：名前（文字列、必須入力＝欠損防止）
  • age INT：年齢（整数、必要なら入れる）

この SQL を実行すると、id・name・age の3列を持つ users テーブルが作成されます。

まとめ

  • CREATE TABLE は「テーブル名 + (列定義...)」で、列定義は カンマ区切り
  • まずは INT / VARCHAR / DATE の使い分けを押さえる
  • PRIMARY KEY（重複防止） と NOT NULL（欠損防止） が最低限の制約
