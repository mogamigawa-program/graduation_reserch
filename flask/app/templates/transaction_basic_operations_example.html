トランザクションの実行例

ここでは COMMIT した場合と ROLLBACK した場合を比較して、 最終的なテーブル状態がどう変わるかを確認します。
見るべきポイントは、「いつ確定したか（COMMITしたか）」です。

比較の核： 同じ UPDATE を行っても、最後が COMMIT か ROLLBACK かで結果が変わる

パターンA：BEGIN → 更新 → COMMIT（変更が残る）

AさんからBさんへ1000円送金する例です。
最後に COMMIT するので、変更は 確定して残ります。

BEGIN; UPDATE accounts SET balance = balance - 1000 WHERE name = 'A'; UPDATE accounts SET balance = balance + 1000 WHERE name = 'B'; COMMIT;

実行前

namebalance
A10000
B8000

COMMIT後（確定）

namebalance
A9000
B9000

結果： COMMIT により確定したため、変更がそのまま残ります。

パターンB：BEGIN → 更新 → ROLLBACK（変更が戻る）

同じ更新を行っても、最後に ROLLBACK すると、BEGIN 以降の変更は すべて取り消されて元に戻ります。

BEGIN; UPDATE accounts SET balance = balance - 1000 WHERE name = 'A'; UPDATE accounts SET balance = balance + 1000 WHERE name = 'B'; ROLLBACK;

実行前

namebalance
A10000
B8000

ROLLBACK後（取消）

namebalance
A10000
B8000

結果： ROLLBACK により確定しなかったため、変更は残りません。

注目ポイント： この2つの違いは「UPDATEの内容」ではなく、最後にいつ確定（COMMIT）したかです。

エラー例・注意例：「いつ確定したか」で結果がズレる

注意例①：BEGINなしでROLLBACKしても戻らない（状況依存）

トランザクションを開始していない状態で UPDATE を実行すると、 環境設定（自動コミット）によっては すぐに確定してしまいます。
その場合、あとから ROLLBACK しても 元に戻りません。

-- BEGINを書かずにUPDATE（自動コミットだと、ここで確定することがある） UPDATE accounts SET balance = balance - 1000 WHERE name = 'A'; -- 後からROLLBACKしても… ROLLBACK; -- 期待どおり戻らないことがある
ポイント： 「いつ確定したか」を見失うと、ROLLBACKできると思っていたのに戻らない、が起きます。

注意例②：確定タイミングを誤ると期待と結果がズレる

例えば、途中で COMMIT してしまうと、その前までの変更は確定してしまいます。
そのあとに ROLLBACK しても、確定済みの変更は戻せません。

BEGIN; UPDATE accounts SET balance = balance - 1000 WHERE name = 'A'; COMMIT; -- ここで確定（この変更はもう戻らない） UPDATE accounts SET balance = balance + 1000 WHERE name = 'B'; ROLLBACK; -- 取り消せるのは「BEGIN～ROLLBACKの範囲」だけ
まとめ： ROLLBACKできるのは、最後に確定（COMMIT）していない範囲だけ。
