DELETE文（全レコード削除）

このページで学ぶこと

  • DELETE FROM テーブル名; は 全件削除（全レコードが対象）になる
  • 実務上の注意（実行前確認・初期化/バックアップ・トランザクション活用）
  • 「空テーブル」になった状態の見方（件数・表示）

1. 全レコード削除とは？

DELETE文は通常、WHERE 句で削除対象を絞り込みます。
一方で、WHERE 句を省略して DELETE FROM テーブル名; を実行すると、 テーブル内の全レコードが削除対象になります。

なお、この操作では テーブル構造（列・制約など）は残ったままであり、 中身（行）だけが空になります。

2. 基本構文

DELETE FROM テーブル名;

WHERE を書かないことで、削除対象を限定せずにすべての行を削除します。

3. 実行前確認（実務上の基本）

全件削除は影響が大きいため、実務では実行前に対象を確認する手順を必須とすることが多いです。 例えば、削除対象が本当に全件でよいかを次のように確認します。

-- 件数で確認 SELECT COUNT(*) FROM students; -- 中身を目視で確認（件数が多い場合はLIMITなどを用いる） SELECT * FROM students;

4. 初期化・バックアップ・トランザクション

全件削除は取り返しが難しいため、以下のような安全策が重要になります。

  • 初期化の導線：学習環境では「初期状態に戻す」機能を用意し、反復実行を可能にする
  • バックアップ：実務では事前にバックアップを取得し、復旧可能な状態を確保する
  • トランザクション：可能であればトランザクション内で実行し、誤りがあればロールバックする
-- 例：トランザクションで安全に実行（DBによって書き方は多少異なる） START TRANSACTION; DELETE FROM students; -- 問題なければ確定 COMMIT; -- 誤りに気づいた場合は取り消し -- ROLLBACK;
⚠ 注意： 全件削除は影響範囲が大きいため、実行前確認と復旧手段（初期化・バックアップ・トランザクション）を前提として扱います。

5. 「空テーブル」になった状態の見方

全件削除後は、テーブルの行数が0になります。
そのため、COUNT と SELECT の表示を用いると「空になった」ことを確認できます。

SELECT COUNT(*) FROM students; -- 0 になる SELECT * FROM students; -- 0行（表示されるデータがない）

表示上は「行が何も出ない」状態になりますが、テーブル自体（列・制約）は残っています。

補足：似た操作との違い

  • DELETE FROM テーブル名; … 中身（行）だけ削除（テーブル構造は残る）
  • TRUNCATE TABLE テーブル名; … 高速に全削除（条件指定不可）
  • DROP TABLE テーブル名; … テーブルそのものを削除
