CREATE TABLE の実行例

このページでやること

CREATE TABLE は「テーブルを作る」だけで終わりではなく、作成後に構造（列名・型）が想定通りか確認するのが大切です。
ここでは、列が2〜4本の小さなテーブルを作り、DESCRIBE で構造を確認する流れを紹介します。

流れ（基本）

① CREATE TABLE を実行 → ② DESCRIBE / SHOW COLUMNS で構造を確認 → ③ もしエラーなら「エラー文 → 原因 → 直す場所」で修正

実行例①：2〜3列の小さなテーブルを作る

まずは列が少ないテーブルから作って、書き方に慣れます。

CREATE TABLE students ( student_id INT PRIMARY KEY, name VARCHAR(50) NOT NULL, enrolled_date DATE );

作成できたら、構造が想定通りか確認します。

DESCRIBE students;

（確認結果イメージ）

FieldTypeNullKeyDefaultExtra
student_idintNOPRI(NULL)
namevarchar(50)NO(NULL)
enrolled_datedateYES(NULL)

実行例②：4列の小さなテーブルを作る（DEFAULT つき）

CREATE TABLE books ( book_id INT PRIMARY KEY, title VARCHAR(100) NOT NULL, price INT DEFAULT 0, published_at DATE );
DESCRIBE books;

Type（型）や Default（初期値）が想定通りになっているかを確認します。

実行例③：3〜4列の小さなテーブルを作る（外部キーの導入）

最後に、別テーブルを参照する外部キーを使った例です（列数は少なめのまま）。

CREATE TABLE borrowings ( borrowing_id INT PRIMARY KEY, student_id INT, book_id INT, FOREIGN KEY (student_id) REFERENCES students(student_id), FOREIGN KEY (book_id) REFERENCES books(book_id) );
DESCRIBE borrowings;

外部キーの詳細まで見たい場合は、次のように確認できます。

SHOW CREATE TABLE borrowings;

典型的なエラー例（エラー文 → 原因 → 直す場所）

ポイント： エラー文は環境やバージョンで多少変わりますが、原因と直す場所はほぼ共通です。

① カンマ不足

-- ❌ カンマが不足している CREATE TABLE users ( id INT PRIMARY KEY name VARCHAR(50) );

エラー文（例）：ERROR 1064 ... near 'name VARCHAR(50) ...'

原因：列定義はカンマ区切り。id と name の間に区切りがない。

どこを直すか：id INT PRIMARY KEY の行末に カンマ を付ける。

-- ✅ 修正 CREATE TABLE users ( id INT PRIMARY KEY, name VARCHAR(50) );

② 余分なカンマ

-- ❌ 最後に余分なカンマ CREATE TABLE items ( id INT PRIMARY KEY, name VARCHAR(100), );

エラー文（例）：ERROR 1064 ... near ');'

原因：最後の列定義の後にカンマが残っている。

どこを直すか：閉じカッコの直前の カンマを削除。

-- ✅ 修正 CREATE TABLE items ( id INT PRIMARY KEY, name VARCHAR(100) );

③ 型名の誤記（スペルミス）

-- ❌ VARCHAR のスペルミス CREATE TABLE people ( id INT PRIMARY KEY, name VARCHR(50) );

エラー文（例）：Unknown data type 'VARCHR'（または類似のエラー）

原因：型名が存在しない（スペルミス）。

どこを直すか：VARCHR を VARCHAR に直す。

-- ✅ 修正 CREATE TABLE people ( id INT PRIMARY KEY, name VARCHAR(50) );

④ 同名テーブル作成（重複）

-- ❌ すでに students が存在するのに再作成 CREATE TABLE students ( student_id INT PRIMARY KEY, name VARCHAR(50) );

エラー文（例）：ERROR 1050 ... Table 'students' already exists

原因：同じ名前のテーブルがすでにある。

どこを直すか：①別名にする／②不要なら DROP TABLE／③安全にするなら IF NOT EXISTS を付ける。

-- ✅ 修正案（安全に作る） CREATE TABLE IF NOT EXISTS students ( student_id INT PRIMARY KEY, name VARCHAR(50) );

⑤ 予約語・不正な識別子

-- ❌ 予約語っぽい名前や、記号を含む名前 CREATE TABLE order ( id INT ); CREATE TABLE user-data ( id INT );

エラー文（例）：ERROR 1064 ... near 'order ...'（または near 'user-data ...'）

原因：予約語として解釈される／ハイフンなどで識別子として解釈できない。

どこを直すか：基本は 名前を変更。どうしても使うなら バッククォート（`）で囲む。

-- ✅ 修正（名前を変えるのが無難） CREATE TABLE orders ( id INT ); CREATE TABLE user_data ( id INT ); -- ✅ どうしてもその名前を使うなら（推奨はしない） CREATE TABLE `order` ( id INT );
